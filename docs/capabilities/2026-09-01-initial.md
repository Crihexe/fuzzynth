# Initial provider capability probe

Date: 2026-09-01

Scope: three tiny Responses API requests plus effective-parameter confirmation

Generated text retained: no

No endpoint URL, API key, chat ID, or generated program is recorded here.

## Results

| Provider | Requested model | Result | Temperature | Reasoning | Verbosity |
|---|---|---|---|---|---|
| alternate | `gpt-5.3-codex-spark` | HTTP 200, exact model ID | omitted; effective `1.0` | requested `none`; effective `low` | requested/effective `high` |
| alternate | `gpt-5.6-luna` | HTTP 200, exact model ID | omitted; effective `1.0` | requested `none`; effective `low` | requested/effective `high` |
| official | `gpt-5.6-luna` | HTTP 200, exact model ID | requested/effective `1.3` | requested/effective `none` | requested/effective `high` |

The alternate endpoint is therefore usable for both requested models and honors
high verbosity, but it normalizes `reasoning.effort=none` to `low`. Temperature
must remain omitted there even though the response reports an effective default
of `1.0`. The official endpoint preserved all three requested Luna parameters.

## Usage and latency observations

These are individual probes, not benchmarks:

| Provider/model | Latency | Input | Output | Reasoning |
|---|---:|---:|---:|---:|
| alternate Spark, default optional parameters | 3179 ms | 35 | 829 | 822 |
| alternate Luna, default optional parameters | 3587 ms | 331 | 84 | 76 |
| alternate Spark, `none` + high | 1709 ms | 35 | 372 | 365 |
| alternate Luna, `none` + high | 1991 ms | 331 | 39 | 31 |
| official Luna, 1.3 + `none` + high | 1927 ms | 35 | 6 | 0 |

Earlier repeated probes showed the same qualitative parameter behavior. Exact
latency and token counts vary and must not be treated as performance conclusions.

## Consequences

- Record both requested and effective response parameters for every generation.
- A successful HTTP response does not prove that a provider honored a parameter.
- On the alternate endpoint, `none` belongs to a coercion test rather than a true
  zero-reasoning experiment unless provider behavior changes.
- Enforce provider-usage, byte, wall-time, and queue limits independently. In the
  Spark probe, reported output including reasoning exceeded the requested
  `max_output_tokens=64` while the response still reported `completed`.
- Investigate alternate Luna's reported 331 input tokens for the same nominal
  prompt that the other probes counted as 35; possible provider-added context is
  a hypothesis, not yet a conclusion.
- Re-run the capability probe periodically and version the observations.
